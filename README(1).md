# B-FLARE — Butterfly-based Leverage & Activation Recommendation Engine

> Find the people who can start the network.

B-FLARE is a data-driven dashboard for identifying the smallest, highest-leverage group of commuters ("seed users") whose activation can cascade into a self-sustaining carpooling/rideshare network within a community hub (e.g. a university or corporate campus). Rather than trying to onboard an entire population at once, B-FLARE surfaces the minimal "butterfly cluster" — a connector, a driver, and a few passengers — most likely to trigger downstream ride creation and viral growth.

## Core Concept

The engine models mobility activation in five stages, matching the app's five screens:

1. **Overview** — Compare community hubs (e.g. campuses) by readiness score and identify the primary bottleneck blocking activation (driver supply, route overlap, or participation density).
2. **Intelligence** — Drill into a selected community's commuters, corridors, and matching potential.
3. **Butterfly** — Surface the minimum effective "Butterfly Cluster": the specific connector, driver, and passengers whose activation unlocks the most downstream ride liquidity, along with the rationale behind the recommendation.
4. **Intervention** — Send outreach/nudges to the recommended seed users and track status (idle → sending → sent → accepted → ride created).
5. **Impact** — Visualize the cascading effect of activating the seed cluster (first rides → repeat rides → new active users → total participants), expressed as a Butterfly Effect Ratio (BER).

## How It Works

The recommendation logic lives in `src/utils/mobilityEngine.ts` and combines several heuristic scores:

- **Route compatibility** — spatial overlap between two commuters' origin/destination zones.
- **Time compatibility** — how well departure times align given each rider's flexibility window.
- **Detour compatibility** — tolerance for route deviation.
- **Capacity score** — available driver seats vs. required seats.
- **Recurrence score** — overlap in weekly recurring commute days.

These combine into a **Ride Opportunity** score:

```
Ride Opportunity = Route × Time × Detour × Capacity × Recurrence
```

Individual commuters are also scored for their standalone **Butterfly Potential**:

```
Butterfly Score = Activation Probability × Ride Potential × Cascade Potential × Bottleneck Fit
```

Community-level readiness and bottlenecks are computed from driver ratio, match liquidity, and participant counts, and cascading activation impact is expressed as a **Butterfly Effect Ratio (BER)**:

```
BER = New Active Users Generated by Seed Cohort ÷ Seed Users
```

> Note: the current implementation uses illustrative/synthetic data (`src/data/syntheticData.ts`) and prototype heuristic weights — see the comment at the top of `mobilityEngine.ts`. These should be calibrated against real-world outcomes before production use.

## Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/) (LTS recommended)

### Installation

```bash
git clone https://github.com/mdshameel/B-FLARE-Butterfly-based-Leverage-Activation-Recommendation-Engine.git
cd B-FLARE-Butterfly-based-Leverage-Activation-Recommendation-Engine
npm install
```

### Development

```bash
npm run dev
```

Starts the Vite dev server on port `3000`.

### Build

```bash
npm run build
```

### Preview a production build

```bash
npm run preview
```

### Type-check

```bash
npm run lint
```

(Runs `tsc --noEmit`.)

### Clean

```bash
npm run clean
```

Removes the `dist` build output and generated `server.js`.
